# 系统架构

## 数据流

```text
K230 视觉节点 ──UART──┐
毫米波雷达节点 ─HTTP──┼──> ESP32-P4 主终端 ──HTTP/局域网──> Web / 小程序 / Android
CSI 接收端 ──HTTP─────┘             │
                                    ├──LVGL 触摸界面
                                    ├──SD 卡历史心率/呼吸率
                                    ├──A7670C 电话/短信
                                    └──云端 LLM / ASR / TTS
```

## 主终端职责

主终端只保存各节点最近一次有效数据，并为每条数据记录时间戳。节点超过新鲜度窗口后不会继续参与跌倒判定。融合流程包含：

1. 读取视觉、毫米波和 CSI 的有效状态。
2. 对超时、无效和通信中断数据做时间门控。
3. 视觉和毫米波作为主证据，CSI 作为辅助证据；主终端依据有效证据组合生成融合分数。
4. 达到阈值后进行告警锁存，避免同一事件重复触发；恢复正常后解除锁存。

CSI 的训练和窗口特征提取在 `tools/csi-toolkit` 中完成。由于 CSI 对环境、天线摆放和信道变化敏感，它在系统中承担辅助确认作用，不单独决定最终告警。

## 节点接口

- K230：主终端 UART RX 接收 K230 的单向状态行，建议格式为 `K230,FALL` 或 `K230,NOFALL`。
- 毫米波节点：周期性向主终端 `POST /api/sensor/ld6002c` 发送 JSON。
- CSI 推理工具：周期性向主终端 `POST /api/sensor/csi` 发送 JSON。
- 主终端：提供 `GET /api/device/status` 和 `GET /api/device/history`，供三端客户端读取。

## AI 交互

AI 功能与跌倒安全链路解耦。LLM 负责对话和健康建议，ASR 负责语音转写，TTS 负责播放文本；三者都通过 menuconfig 配置 URL、模型和密钥，未配置时主终端仍可运行本地界面和传感器链路。
